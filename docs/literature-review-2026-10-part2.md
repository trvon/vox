## B. Keeping Kokoro without espeak-ng

### Official 2.x guidance

[Removal PR #4055](https://github.com/k2-fsa/sherpa-onnx/pull/4055) specifies two frontends:

1. Built-in **lexicon**.
2. **External phonemization**, passed through `GenerationConfig::phoneme_codepoints`.

`data_dir` is deprecated and ignored. The official [English lexicon example](https://github.com/k2-fsa/sherpa-onnx/blob/master/rust-api-examples/examples/kokoro_tts_en_lexicon.rs) is not an OOV solution. The companion [phonemization example](https://github.com/k2-fsa/sherpa-onnx/blob/master/rust-api-examples/examples/kokoro_tts_en_phonemize.rs) uses optional **GPL piper-phonemize**. There is no verified official, permissively licensed English neural-G2P recommendation.

### Preferred permissive implementation

**Text normalization → dictionary/POS/morphology → neural OOV → validated Kokoro phonemes.**

- **[misaki-rs](https://github.com/MicheleYin/misaki-rs):** MIT Rust port; disable **default features**, because its default enables espeak. It exposes a custom fallback trait. Without fallback it may spell unknown words—not pronounce them.
- **[Phonemoro](https://github.com/lastleon/phonemoro):** MIT, using Apache-2.0 Misaki data. Worth evaluating, not assuming pronunciation parity.
- **[OpenPhonemizer ONNX](https://huggingface.co/nekwo/openphonemizer-en-us-onnx):** especially practical OOV candidate; third-party export supplies a **31 MB fp16** model and declares model/dictionary **BSD-3-Clause-Clear**. Run through Rust ONNX Runtime bindings; validate conversion and dialect mapping.
- **[DeepPhonemizer](https://github.com/as-ideas/DeepPhonemizer):** MIT code; ONNX conversion is possible engineering work, not a verified drop-in Rust package. Audit checkpoint terms separately.
- **[CharsiuG2P](https://github.com/lingjzhu/CharsiuG2P):** MIT code, multilingual ByT5 architecture. Decoder orchestration/export is heavier; the exact checkpoint’s weight license was **not verified**. Do not ship on repository-license assumptions.
- **[CMUdict](https://github.com/cmusphinx/cmudict)** plus neural OOV is permissively usable, but ARPAbet conversion must preserve stress and handle contextual heteronyms.

Misaki’s useful design is contextual dictionary lookup plus fallback. Historical fallback uses espeak; [current source](https://github.com/hexgrad/misaki/blob/main/misaki/en.py) also contains a BART fallback. Its checkpoint licensing/export maturity needs separate verification.

### Phoneme compatibility

Kokoro v1.x English expects **Misaki’s model-specific IPA-derived alphabet**, not arbitrary IPA or ARPAbet. Sherpa’s [lexicon generator](https://github.com/k2-fsa/sherpa-onnx/blob/master/scripts/kokoro/v1.0/generate_lexicon_en.py) imports Misaki pronunciations.

Examples: diphthongs use symbols such as **`A` = /eɪ/** and **`O` = /oʊ/**; rhotics, affricates, stress and vowel length require dialect-aware handling. Follow [Misaki’s conversion rules](https://github.com/hexgrad/misaki/blob/main/misaki/espeak.py), then validate **every codepoint against the actual archive’s `tokens.txt`**. Do not silently discard unsupported symbols.

For normalization, use MIT [Rust `num2words`](https://docs.rs/num2words/latest/num2words/) plus explicit rules for dates, money, decimals, units and abbreviations. Test ambiguities such as `2026`, `10/11`, `1.5 GHz`, `Dr.` and version numbers. G2P alone cannot solve these.

**GPL consequence:** statically or dynamically linking espeak-ng into a distributed combined application generally requires GPL-compatible distribution under GPL obligations, including corresponding source—not an MIT-only binary. Vox’s own source can retain MIT notices. A separately invoked executable is a different legal arrangement, not an automatic exemption. The existing 1.13.8 bundled path also deserves review. Not legal advice.

## D. Forced-split reconciliation

Use **timestamp-constrained suffix/prefix alignment**, not global string deduplication.

1. Decode approximately **20–30-second** chunks; prefer silence boundaries.
2. Start with **two seconds shared overlap** at forced boundaries—about one second of padding on either side. This is a tuning recommendation, not a published optimum.
3. Convert sherpa token timestamps to absolute sample coordinates. Group subwords into words; preserve original punctuation separately.
4. Align only the previous tail/current head using normalized tokens and timestamps. Use bounded **LCS/edit alignment**, rejecting matches far apart acoustically.
5. Select a seam near the overlap midpoint; retain the hypothesis with more interior acoustic context. Hold the tail until its successor arrives.
6. If alignment fails, re-decode a larger boundary window or flag it. Never delete a legitimate repeated phrase merely because its text matches.

[NeMo buffered inference](https://github.com/NVIDIA-NeMo/Speech/blob/main/nemo/collections/asr/parts/utils/streaming_utils.py) provides LCS-merge precedent. [WhisperX](https://arxiv.org/abs/2303.00747) supplies forced alignment, not a universal overlap-merging algorithm. [LocalAgreement-2](https://arxiv.org/abs/2307.14743) commits prefixes stable across two successive decodes; reserve its repeated computation for previews.

Parakeet makes this implementable without a second alignment model. Token starts are not automatically accurate word-end boundaries.

## E. Multi-hour diarization

Use **pyannote segmentation 3.0 + an English-trained embedding model**, initially `3dspeaker_speech_campplus_sv_en_voxceleb_16k.onnx`. Sherpa also supports ERes2Net, WeSpeaker and NeMo embeddings ([models/examples](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html)).

- **Licenses:** segmentation 3.0 is **MIT**, although upstream download access is gated. [3D-Speaker](https://github.com/modelscope/3D-Speaker) is Apache-2.0; retain/check checkpoint notices. Sherpa’s alternative **Reverb diarization** is explicitly **non-commercial**—exclude it from the default.
- **Scaling:** neural passes approximately follow audio duration, but [sherpa clustering](https://github.com/k2-fsa/sherpa-onnx/blob/master/sherpa-onnx/csrc/fast-clustering.cc) allocates a dense condensed **double-precision pairwise distance matrix**: about **400 MB at 10,000 embeddings**, **3.6 GB at 30,000**. Whole-file float32 mono audio adds about **230 MB/hour** at 16 kHz.
- **Thresholds:** complete-linkage clustering uses cosine dissimilarity; larger thresholds merge more speakers. Sherpa’s **0.9** example is recording-specific, not a universal setting. Tune with labeled room audio; specify speaker count when reliably known.
- **Architecture:** process bounded blocks, persist embeddings, and reconcile identities through global exemplars. Independent per-block speaker numbers are not stable identities.
- **Assignment:** assign each word by greatest temporal overlap with diarization intervals; split transcript segments at speaker changes. Preserve simultaneous labels or “overlap/uncertain” rather than forcing one speaker.

Comparable multi-hour CPU RTF remains **unverified**.

## G. Punctuation/casing

Do **not** automatically repunctuate Parakeet, Qwen or Cohere output. Preserve native presentation; enable Cohere’s punctuation/ITN and Canary’s PnC.

For unpunctuated streaming models, sherpa offers:

- **`sherpa-onnx-online-punct-en-2024-08-06`**: English CNN-BiLSTM, punctuation **and casing**.
- **`sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12`**: offline Chinese/English punctuation; documented English output does not establish recasing.

See [model documentation](https://k2-fsa.github.io/sherpa/onnx/punctuation/pretrained_models.html). Audit weight licenses separately; punctuation changes should not rewrite raw timing/alignment records.
